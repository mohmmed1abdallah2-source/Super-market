# Global Enterprise Supermarket & Retail ERP

تطبيق Flutter لإدارة سوبرماركت ونقاط بيع ومخزون وحسابات، بواجهة عربية RTL، وتشغيل محلي Offline-first باستخدام SQLite. نطاق المنتج هو إدارة البيع داخل المتجر، وليس إنشاء متجر إلكتروني.

## النطاق الوظيفي

- كتالوج أصناف متعدد الوحدات والباركود وأسعار التجزئة والجملة.
- قراءة EAN-13 وباركود ميزان قابل للتهيئة.
- شاشة POS متعددة الفواتير.
- دفتر «له وعليه» وسندات قبض وصرف وقيود محاسبية.
- مخزون ودفعات FEFO وجرد وإتلاف وتحويل بين المستودعات.
- طابور مزامنة محلي يحتفظ بهويات العمليات لإعادة المحاولة.

## المعمارية الحالية وحدودها

- SQLite هو مخزن التشغيل المحلي؛ تحفظ العمليات محليًا أولًا.
- يوجد خادم Dart/Shelf وطبقة PostgreSQL تدعم حاليًا مزامنة ذرية لعمليات الأطراف والمبيعات والسندات والمشتريات والجرد والإتلاف والتحويل.
- محرك SQLite يقبل حقن `ApiClient` لإرسال طابور المزامنة. وجود هذا المسار في المصدر لا يعني أن جلسة مصادقة حقيقية أو عنوان API منشور قد تم إعدادهما في التطبيق.
- ما زالت شيفرة Firebase/Firestore موجودة كتكامل اختياري/قديم؛ لا تخلط بينها وبين مسار PostgreSQL API ولا تشغّل مسارين لنفس البيانات دون قرار انتقال موثق.
- مصادقة الخادم الحالية تعتمد رموزًا ثابتة محددة لكل فرع في إعدادات البيئة و`X-Branch-Id`. هذا أساس تطوير محدود، وليس نظام حسابات مستخدمين وصلاحيات إنتاجيًا.
- العزل الموجود حاليًا هو عزل `branch_id` داخل قاعدة PostgreSQL واحدة. **العزل متعدد المتاجر بقاعدة مستقلة لكل متجر، وقاعدة تحكم للمالكين والعضويات، وقاعدة SQLite مستقلة لكل متجر لم تكتمل بعد.**
- لا تضع كلمات مرور PostgreSQL أو رموز الفروع أو مفاتيح الخدمات داخل التطبيق أو المستودع.

## إنشاء ملفات المنصات أول مرة

إذا لم تكن ملفات المنصة موجودة في نسخة العمل المحلية، ولّدها بواسطة Flutter SDK:

```bash
flutter create --platforms=android,windows .
flutter pub get
dart format .
flutter analyze
flutter test
```

## التشغيل المحلي

```bash
flutter run
```

بيانات الدخول المحلية الافتراضية الموجودة في بعض إعدادات التطوير ليست آمنة للإنتاج. يجب استبدالها بنظام هوية موثوق وتطبيق صلاحيات حقيقية قبل أي استخدام فعلي.
