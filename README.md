# Global Enterprise Supermarket & Retail ERP

تطبيق Flutter لإدارة سوبر ماركت بنظام بيع مباشر فقط، بواجهة عربية RTL ووضع ليلي، وقاعدة SQLite محلية مع مزامنة Firebase اختيارية.

## النطاق الحالي
- كتالوج أصناف متعدد الوحدات والباركود وأسعار التجزئة والجملة.
- قراءة EAN-13 وباركود ميزان قابل للتهيئة.
- شاشة POS متعددة الفواتير (حتى 8 تبويبات).
- دفتر «له وعليه» وسندات قبض وصرف.
- قيد محاسبي مزدوج، وحركات مخزون محلية.
- طابور مزامنة مضغوط مع مراقبة تقديرية لحصة Firebase.

لا يتضمن المشروع متجراً إلكترونياً أو طلبات شراء عبر الإنترنت.

## إنشاء ملفات المنصات أول مرة
المستودع يحتوي ملفات Dart وملف pubspec، لكن مجلدات المنصات الأصلية يجب توليدها بواسطة Flutter SDK:
\`\`\`bash
flutter create --platforms=android,windows .
flutter pub get

\`\`\`

## التشغيل
\`\`\`bash

\`\`\`

بيانات الدخول الأولية للتطوير المحلي:
- المستخدم: \`admin\`
- كلمة المرور: \`123456\`
- رمز المدير التجريبي: \`9999\`

هذه بيانات تطوير فقط. يجب تغييرها وإضافة تخزين كلمات مرور مملح وقوي وإدارة صلاحيات حقيقية قبل استخدام النظام في بيئة فعلية.

## Firebase (اختياري)
1. أنشئ مشروع Firebase وأضف تطبيق Android/Windows المدعوم حسب المنصة.
2. نفّذ \`dart pub global activate flutterfire_cli\` ثم \`flutterfire configure\`.
3. أضف تهيئة \`Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)\` في نقطة بدء التطبيق باستخدام ملف الإعدادات الذي يولده FlutterFire.
4. انشر قواعد \`firestore.rules\` بعد تهيئة Firebase Authentication وCustom Claims موثوقة تتضمن \`branch_id\` و\`role\`.
5. أنشئ \`FirestoreSyncTransport(FirebaseFirestore.instance)\` ومرره إلى \`FirebaseFreeTierSyncService\` في طبقة التطبيق.

لا تضع مفاتيح حساب خدمة داخل تطبيق الهاتف. لا تفترض أن Spark يوفر Cloud Functions. تحديث ملخص اليوم من العميل مسموح فقط للمستخدمين ذوي الدور والفرع المصرح بهما وفق القواعد؛ راجع النموذج الأمني قبل الإنتاج.

## تنبيه الحصة
سقف 18,000 كتابة يومياً حد أمان تطبيقي مقترح في هذا المشروع، وليس وعداً من Firebase. كل مستند دفعة وكل تحديث لملخص اليوم عملية كتابة مستقلة. تحقق من صفحة Firebase الرسمية الحالية ومن حجم المستندات ومعدل التحديث قبل الإطلاق.
